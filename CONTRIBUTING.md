# Contributing to token.observer

Thanks for wanting to contribute! token.observer is an open investigation into
the real cost of LLM inference — local hardware vs rented cloud GPUs vs paying
per token. The project is MIT licensed and PRs are welcome, whether you are
fixing a typo, adding a model, or improving the math.

## Prerequisites

- **Node.js 20** (what CI uses — see `.github/workflows/deploy.yml`)
- **npm** (the repo pins `npm@11.11.1` in `package.json`)

## Local setup

```bash
npm install
npm run dev        # dev server at http://localhost:5173
```

`npm run build` produces a static build in `dist/` and `npm run preview` serves
the production build locally so you can verify it looks right before pushing.

## Checks before opening a PR

- Run **`npm run build`** — it must succeed. This is the main smoke test; with
  no transpiler step at import time, template/import errors show up here.
- Run **`npm run preview`** and click through the pages you changed.
- There is currently **no automated test suite**, so a manual smoke test of
  your change in the dev server is the expected check.

> Note: `AGENTS.md` describes a Vite+ (`vp`) toolchain used by automation in
> some environments. If you have the `vp` CLI installed you may also run
> `vp check` (`vp lint`, format, type checks) and `vp test`. For everyday
> contribution, the `npm` commands above are the source of truth.

## Commit and PR conventions

- Use **Conventional Commits**: `feat:`, `fix:`, `docs:`, `chore:`, etc., with
  a short summary in the subject line.
- **One focused change per PR** with a descriptive title, and reference the
  issue it addresses (e.g. "Closes #12").
- The daily `chore: update prices` commits are generated by CI — don't hand-edit
  or mimic them.
- Keep the diff minimal; don't commit generated artifacts (`dist/` is gitignored).

## Where different contributions go

| Change | Where |
| --- | --- |
| **Add / update a model** | `src/data/models.json` — add an entry with `apiProviders` (name + input/output per $/M), `benchmarks`, `verdict` (VIABLE / HARD / IMPRACTICAL), and `tier` |
| **GPU / hardware configs** | `src/data/models.json` → `GPU_CONFIGS` |
| **Usage profiles** | `src/data/models.json` → `USAGE_PROFILES` |
| **Price update pipeline** | `scripts/update-prices.js` — read `scripts/README_PRICES.md` first |
| **UI / pages** | `src/pages/*.jsx`, `src/components/*.jsx` |

Always verify pricing against current sources before changing numbers — see the
link list in `README.md` ("Keeping prices current").

## Reporting issues

Use the issue templates. Please search existing issues first, and include a
title, steps to reproduce (for bugs), or a clear motivation and proposed
solution (for features). Include environment details (local dev vs deployed
site, browser/OS) and screenshots where helpful.

## Code of conduct

Be kind and assume good faith. Keep discussion focused on the work. Harassment
or personal attacks are not welcome.
